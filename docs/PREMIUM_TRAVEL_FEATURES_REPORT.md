# Premium travel features — implementation and validation

Before You Go retrieval was subsequently repaired: [current trust tiers, evidence matching, snapshot retention and targeted validation](BEFORE_YOU_GO_REPAIR_REPORT.md). That repair requires no new migration and supersedes the original official-only retrieval description below.

Implemented locally on 7 October 2026: **Add to Calendar**, **Before You Go**, and **Quick Itinerary / Full Travel Book**. All use the existing trip entitlement and upgrade flow. Existing unrelated workspace changes were preserved. No deployment, production database changes, service restart, DNS changes or real secrets were added.

1. **Files changed/new.** New server modules: `server/premium-travel/{calendar,essentials,essentials-provider,essentials-sources,migrate,router,travel-book}.js`. New UI/shared files: `src/components/trip/PremiumTripFeatures.jsx`, `src/styles/premium-trip-features.css`, `src/lib/country-codes.js`. Integrations: `server/app.js`, `server/migrate.js`, `server/billing/entitlements.js` (feature labels), `src/api/client.js`, `src/pages/{Dashboard,Itinerary}.jsx`, `src/components/trip/TripOverview.jsx`. Four targeted test files and `scripts/check-premium-travel-browser.mjs` were added. Existing Quick PDF renderer was preserved.

2. **Migration.** One idempotent, additive `trip_essentials_snapshots` table stores structured JSON, owner/trip IDs, passport country code, context hash and retrieval timestamp. Composite ownership foreign key cascades with trip deletion. Integrated into the existing migration command. Applied in `tripsync_test` during browser validation and, separately, only this new migration in the confirmed local `tripsync` database after checking loopback host and non-production configuration. No production database was accessed. Other installations need the normal `npm run db:migrate` before using Essentials.

3. **Premium gating.** Authenticated server routes call the existing ownership and `requireFeature` helpers. Pro, eligible Trip Packs, grants and grandfathering follow existing rules, including the existing enforcement switch. Quick PDF already used premium enforcement and retains it. Free travelers see locked choices and the Before You Go card; clicks open the existing paywall. These actions do not reserve or consume another trip credit. Browser checks confirmed no new credit-ledger entries.

4. **Calendar behavior.** A single compact **Download Trip** header action opens the PDF/calendar chooser. Calendar supports entire trip or selected days and optional transfers. Events come exclusively from the saved itinerary. Includes stable hashed event UIDs, timestamps, locations, safe descriptions and authenticated trip links, with RFC escaping, CRLF and UTF-8 line folding. Buffer/free-time blocks are excluded; incomplete event ranges are skipped with visible feedback. The dialog explains stale saved plans and that imports do not synchronize automatically. Format reference: [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545).

5. **Timezone handling.** Saved local schedule values use the trip's recorded IANA timezone, converted to UTC for calendar interoperability. Overnight/cross-date ranges use existing interval helpers. Missing timezone, nonexistent DST times and ambiguous DST times produce an explicit error instead of guessed dates. No browser-timezone inference.

6. **Essentials architecture.** A provider abstraction reuses the existing server-side OpenAI Responses infrastructure, domain-filtered `web_search`, structured output and safe public-page reader. Only destination country, dates and optional passport country are sent. Country sections derive from destination, saved stays and scheduled selections. A context hash invalidates snapshots when countries, dates or passport change. Opening the panel reads saved data; only explicit refresh retrieves new material. Search integration follows [OpenAI's official web-search documentation](https://developers.openai.com/api/docs/guides/tools-web-search).

7. **Sources/freshness.** A conservative 22-country destination-authority registry plus official advisory links governs retrieval. Candidate facts require completed search-source provenance, an allowed authority URL and an exact evidence quotation independently found on the retrieved page. Entry facts additionally require passport nationality and a destination entry-authority source. No readable evidence means no factual claim. The UI exposes sources and genuine checked dates; unverified sections remain clearly unverified. Snapshots become stale after 24 hours; refreshes coalesce and have a five-minute cooldown. Only a country code is remembered for passport preference, never identity documents. Entry, health and safety sections remind travelers to verify the linked authorities.

8. **Quick PDF.** Existing content, renderer and saved-plan behavior remain intact. The chooser adds a clear format selection; both formats use existing premium access. Actual Quick PDF download succeeded (eight pages for the deliberately dense test fixture).

9. **Full Travel Book.** A branded cover presents trip dates, travelers and accommodation. Day sections combine compact saved timelines, maps, transfer details and booking labels. Bookings/documents and saved source-checked Essentials appear near the end. Available weather summaries are optional and provider failures do not block export. The representative five-day fixture produced **10 pages**, including a day with 18 visits. Content can spill to extra pages rather than being truncated.

10. **PDF maps.** Reuses the Interactive Trip Maps normalized stop/order model and real coordinates. Accommodation uses H; visited stops are numbered. Dashed connectors indicate itinerary order, with an explicit schematic-map explanation. Missing coordinates are disclosed. Existing Google Maps routes remain clickable, with one useful live-route QR per day. No Google tiles, road geometry, Static Maps or fabricated coordinates.

11. **Bookings/tickets/Wallet.** Saved booking/provider labels, dates, confirmation status and attachment counts are summarized where available. Ticket and Wallet links lead back to authenticated application destinations. Original documents stay in Travel Wallet; they are not appended or exposed through public file URLs. Booking credentials, confirmation numbers and private notes are excluded. Affiliate linking and Wallet behavior are unchanged.

12. **Security/privacy.** New endpoints require sessions, explicit owner checks and parameterized queries. Responses/downloads are private and not cacheable. Cross-user requests return 404; anonymous requests return 401. Server keys never enter browser responses. HTML is escaped and rendered using the existing restricted PDF renderer. Safe source retrieval reuses public-DNS/redirect protections. No itinerary regeneration or edits occur during export/Essentials viewing.

13. **Desktop/mobile.** One representative Chrome session covered desktop **1440 px** and mobile **390 px**: locked Free actions/paywall, premium PDF chooser, calendar selection, real downloads, Essentials sources/passport, Overview/final-day placement and dialog bounds. No horizontal overflow, browser exceptions, saved-item mutations or additional credits were detected. Existing dialog/focus patterns and reduced-motion handling are reused. Screenshots show fixture data, not verified real-world travel advice.

14. **Targeted checks actually run.** Calendar: 6; Destination Essentials: 6; Quick/Full renderer: 4; entitlement: 3 — **19 passing tests**. Executed together with `node --test` for those four files. One calendar test initially matched a folded UID incorrectly; its assertion now unfolds valid lines, and only the six calendar tests were rerun. Targeted TypeScript and ESLint checked the four affected React components/pages; a JSX delimiter caught by those checks was corrected and the affected checks rerun. Browser/API checks used the separate `tripsync_test` MySQL database and cleaned fixture users. OpenAI/search and weather results were fixtures: no paid AI or Google Maps calls. No full suite or unrelated regression tests were run.

15. **Production build.** Exactly one `npm run build` for this coordinated task: **passed**, 2,541 modules transformed. Vite reported the existing large-chunk warning; it did not fail the build.

16. **External requirements.** Existing MySQL, application-URL settings and Chrome PDF renderer remain required. Live Essentials retrieval needs the existing server OpenAI key/model configuration, a Responses model supporting web search/structured output, and outbound access to OpenAI and official authority pages. No new keys or paid calls were added. Without reliable retrieval, official links and honest unverified states are shown. Printable maps require no new Google key. Weather uses its existing providers/configuration.

17. **Remaining limits.** Calendar is download/import only; external calendar apps were not individually tested. DST ambiguities require a saved-time correction. Authority coverage is intentionally conservative; unknown countries, inaccessible pages or JS-only official sites may yield only advisory links. Live paid OpenAI retrieval was not executed, so its deployment configuration still needs a real provider check. Context snapshots are private and persistent; changing passports/destinations requires a new explicit refresh. Full Book page count depends on actual content; no automatic guarantee of ten pages. PDF links require network access/sign-in where appropriate; originals remain in Wallet. Quick PDF intentionally retains its existing density/content.
