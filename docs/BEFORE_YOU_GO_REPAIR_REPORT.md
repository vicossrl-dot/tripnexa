# Before You Go — retrieval repair

The later [fast-guide refactor report](BEFORE_YOU_GO_FAST_GUIDE_REPORT.md) describes the current AI-first architecture, bounded supplemental verification, updated UI and standalone Essentials PDF. The implementation and validation below are the earlier historical repair.

Local implementation and coordinated validation completed on 7 October 2026. This repair is confined to Destination Essentials retrieval, snapshot handling and its existing UI. No deployment or production data changes.

1. **Root cause.** A small flat domain registry, exact quotation matching and mandatory direct page access discarded legitimate practical facts. Retrieval errors were swallowed, and replacing a snapshot could erase good same-context evidence during a temporary failure.

2. **Files changed.** Updated `server/premium-travel/essentials-sources.js`, `essentials-provider.js`, `essentials.js`; added `essentials-policy.js`. Updated only the Essentials portions of `src/components/trip/PremiumTripFeatures.jsx` and added a scoped provenance-label style in `src/styles/premium-trip-features.css`. Replaced the relevant tests in `server/tests/destination-essentials.test.js`; added `scripts/check-essentials-repair-browser.mjs` and this report. Calendar, PDF, Maps, Weather, billing, Wallet and itinerary implementation files were not edited for this repair.

3. **Official / trusted / AI architecture.** The registry now groups entry, tourism, transport, emergency, health and practical authorities. Japan has additional public transport, emergency and health sources. Discovery accepts country-specific government namespaces, with Japan local-government and Canadian government namespaces also recognized. Arbitrary “official” titles or `.org` domains are insufficient. Curated reference organizations/operators include IEC, IATA, Time and Date, and Japanese rail operators in the appropriate practical categories. Retrieved URLs must be present in completed search provenance and pass the source policy. Official evidence takes precedence over trusted alternatives. One grouped practical search, one entry search when nationality exists, and at most one unresolved-only AI fallback reuse the existing Responses provider; no new API.

4. **AI fallback permitted.** Power/plugs, connectivity, transport basics, tipping/customs, general etiquette, harmless practical basics and non-critical tips. Maximum two short facts per section. Server-generated metadata is `sourceType: ai_general`, `sourceUrl: null`, `checkedAt: null`. The existing UI displays **AI general guidance**, without a fake citation. Saved single-country currency/timezone take priority and are excluded from retrieval requests. The fallback call receives only country and unresolved section keys.

5. **AI fallback forbidden.** Entry/visa/passport/immigration, health and vaccination requirements, safety warnings, emergency numbers, laws/restrictions and drinking-water safety. High-risk section keys and risk-bearing wording are checked server-side, including facts misplaced in practical sections. Drinking-water safety requires readable official evidence in this conservative implementation. General etiquette is allowed; legal claims are not. Missing evidence leaves an honest authority-link fallback. Passport nationality is never derived from departure country. Albania remains Albania when selected, its code is remembered, and **Choose passport country** stays visible above the selector.

6. **Evidence validation.** HTML entities, Unicode apostrophes/quotes/dashes, whitespace, line breaks and common punctuation are normalized. High-risk quotations must match the normalized readable page; numeric claims must also occur in their evidence quotation. Low-risk passages may use a tightly bounded token match with numeric/negation checks. Citation fragments and tracking parameters no longer cause provenance mismatches. Page reads remain bounded and use the existing public-DNS/redirect protections. Unreadable pages may supply low-risk facts only when actual tool-supplied snippet text supports the quote; the model's own quote is never sufficient by itself. No snippet relaxation for high-risk facts.

7. **Snapshot/cache.** Existing table and context hashes are retained. Existing JSON is normalized on read, including legacy official facts without `sourceType`. Successful sections merge with valid same-context official/trusted facts checked within 24 hours. AI-only replacements cannot displace valid sourced facts. Retained facts keep their original checked dates; country freshness conservatively uses the oldest retained check. Expired facts are not retained during refresh. Destination/date/passport invalidation, five-minute cooldown, coalescing and on-demand behavior remain. Opening/reloading does not regenerate AI content. Refresh shows **Checking travel information…** and **Travel essentials updated.**

8. **Diagnostics.** Fixed `[essentials] <country-code> <event>` messages identify unreadable pages, practical/entry retrieval failures, unavailable entry verification and fallback success/failure. Messages contain no provider error bodies, URLs, API keys, emails, passport details or documents. Page failures are logged once per country retrieval; no per-fact success flood. Example browser-fixture events: `practical-no-usable-evidence`, `entry-verification-unavailable`, `ai-fallback-generated`.

9. **Database migration required: no.** Only snapshot JSON provenance metadata changed. Browser checks used the existing separate `tripsync_test` database and cleaned fixture users. No application/production database migration was performed for this repair.

10. **Targeted validation.** `node --test server/tests/destination-essentials.test.js`: **15 passed**, covering Japan/Albania, context invalidation, trusted/random sources, normalized/fuzzy evidence, unreadable pages/snippets, high-risk rejection, grouped retrieval, AI labels/metadata, partial failures, same-context retention, cooldown and safe logs. Targeted TypeScript and ESLint for the affected component passed. One Chrome session tested **1440 px / 390 px**, using the actual authenticated refresh route/provider wrapper with simulated OpenAI responses. Verified passport persistence, permanent selector caption, JPY/Asia-Tokyo values, all provenance labels, progress/success copy, strict entry/emergency gaps, retained source-backed facts, no fake AI links, no overflow, no browser errors and no saved itinerary changes. No unrelated tests or full suite were run.

11. **Build.** Exactly one `npm run build`: **passed**, 2,541 modules transformed. Existing Vite large-chunk warning remains informational. No repeated builds.

12. **Remaining limitations.** Paid live OpenAI retrieval was not executed; provider behavior and full destination coverage still need a real configured-environment check. OpenAI documents source URLs but does not guarantee raw snippets in every response: when snippets are absent and pages are unreadable, practical sections can fall back to labeled AI guidance, while high-risk sections remain unverified. Government namespace discovery is intentionally conservative; countries with other authority-domain conventions need registry additions. Source evidence and risk guards reduce unsupported claims but do not mathematically prove every generated summary; travelers should check the linked authority for important requirements. No new configuration/API key is required beyond the existing server setup.

Source integration uses [official OpenAI web-search documentation](https://developers.openai.com/api/docs/guides/tools-web-search). Additional Japan authority categories were checked against [Japan National Tourism Organization](https://www.japan.travel/en/plan/), [Fire and Disaster Management Agency](https://www.fdma.go.jp/en/) and [Tokyo Metro](https://www.tokyometro.jp/en/).
