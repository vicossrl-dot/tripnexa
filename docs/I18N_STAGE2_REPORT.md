# Server content internationalization

Changes are local to C:\travel. No deployment, commit or push. No stage-2 entity/schema changes or new database migrations. The existing `User.ui_locale` preference is reused.

Request locale is carried by `X-TripNexa-Locale` and held in AsyncLocalStorage: explicit request choice, authenticated preference, supported browser language, then English. Admin requests bypass localization. The existing shared translation-key runtime now includes six server catalogs; server errors retain HTTP statuses, error codes and field identifiers. Static server copy, auth email subjects/bodies, shared-trip labels, restaurant display descriptions and PDF/calendar labels use the same keys. Browser errors already received in another language can change language without changing their parameters.

Responses requests append the selected prose language while preserving structured schemas, property names, enums and internal values. Official names, user-selected trip names, venue names, source URLs and quoted evidence stay canonical. Before You Go additionally carries `displayLocale` in its request context, but its canonical briefing remains English for the existing lexical/evidence validators. Locale-specific prose is a display projection after validation. Official evidence, authority checks, freshness, passport applicability, completeness and legal/emergency restrictions were not weakened. PDF rendering still validates the canonical snapshot before substituting displayed text.

Saved generated reasons, descriptions of itinerary steps and Before You Go facts are translated through an ownership-scoped projection. Canonical database content is never updated by a language change. The persistent private cache defaults to `.local/locale-translations`; `LOCALE_TRANSLATION_CACHE_DIR` can designate another private writable directory. Cache keys include owner, locale, exact source content and translation-policy version. Per-source entries allow PDF/public readers to reuse subsets. Model provenance prevents translating newly generated content already in the requested language. Static dictionary matches do not call AI. Concurrent requests coalesce; a filesystem lease bounds cross-process calls, and failed translations have a five-minute cooldown. Invalid arrays, changed numbers/URLs and provider failures fall back to the canonical source. Only actual new translation calls enter existing AI quotas/billing; cache hits do not consume additional planning calls.

Trip display prepares saved translations on locale/content changes, including an existing premium essentials snapshot for the saved passport context. Shared-trip readers use only the existing public projection and cache; they cannot request paid anonymous translations or access private source fields. PDF and calendar downloads read cache only and never generate AI translations. Missing cached prose falls back to its canonical source; downloading in a new language does not spend a model call. Private notes, ticket URLs, booking credentials, passport identity, internal enums and evidence excerpts are excluded from the translation projection.

All PDF formats embed the bundled Noto Sans variable TTF through a data URL, explicitly allow that font in the PDF CSP, wait for fonts to load, and keep remote network access/scripts disabled. This avoids an operating-system font dependency under Chromium/CageFS. The license is bundled in `server/assets/fonts/OFL.txt`. Font source: the official Google Fonts `ofl/notosans` repository; SHA-256 `bfb7bb691513f12e734dc346c03a03f784912432d7e3fa8e56efcf906fe86b3d`. Production Linux/CageFS was not accessed; validation used installed local Chrome.

An attempted external batch translation of static application copy was rejected by automatic approval review. The command was not executed, no catalog was uploaded, and its script was removed. The remaining static catalogs were completed locally instead. Live provider calls were not used in validation; AI responses were mocked.

Validation uses local Node 22.23.3:

- `npm run lint` and `npm run typecheck`: passed.
- `npm run i18n:check`: 1,722 UI keys plus 546 shared server keys; six-locale key/interpolation parity passed. This does not claim a new translation review of the entire stage-1 UI catalog.
- `npm run i18n:server-check`: 394 audited user-facing static messages/templates; no missing keys. This checks the current user-facing route/helper scope, excludes Admin/internal values, and permits English fallback for unknown future messages.
- `npm test`: 197/197 tests passed; includes locale isolation, AI schema/evidence preservation, offline fallbacks, localized emails, calendar contracts, canonical-content preservation, cache reuse/concurrency/invalidation/failure cooldown, shared copy and six-locale PDF HTML/fonts.
- MySQL regression: passed against loopback-only `tripsync_test`, including saved preference versus request choice, source/enums remaining unchanged, owner isolation and zero AI billing for static translations. Existing migration was rerun idempotently on this test database only.
- Eight actual Chromium PDF exports passed: Quick PDF in all six locales, Before You Go and Full Travel Book in Russian. The fixtures assert embedded Noto Sans and searchable Unicode/Cyrillic maps.
- `npm run build`: passed; Vite reports its large-chunk warning.
